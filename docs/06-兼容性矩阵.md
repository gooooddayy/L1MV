# 06 · 兼容性矩阵

> 一句话原则：**不猜浏览器，启动时问它**。缺什么就关掉哪条路、说清楚原因，而不是等点了导出才炸。
> 但有些东西连「问」都不可靠（AAC 支持性查询会撒谎），那些地方靠真编一次来判断。

## 1. 浏览器能力总表

| 能力 | Chrome / Edge | Safari | Firefox |
|---|---|---|---|
| 最低可用版本 | **94+** | **16.4+**（部分） | **130+**（桌面） |
| 完整体验（快速编码 + 音频） | 94+ | **26.0+** | 130+ 桌面 |
| `VideoEncoder` / `VideoDecoder` | ✅ | 16.4+ | 130+ |
| `AudioEncoder` / `AudioDecoder` | ✅ | **仅 26.0+** | 130+ |
| `ImageDecoder` | ✅ | 26.0+ | ❌ |
| `MediaRecorder` | ✅ | ✅（只能 mp4） | ✅（只能 webm） |
| `canvas.captureStream` | ✅ | ✅ | ✅ |
| `performance.memory` | ✅ | ❌ | ❌ |
| `inert` | 102+ | 15.5+ | 112+ |
| 本项目的实际产物 | MP4（H.264+AAC） | 26+ → MP4；16.4–18 → 录制 MP4 | 录制 WebM → 自动转 MP4 |

**注**：Firefox Android 没有 WebCodecs（桌面版才有）。Safari 16.4–18.7 只有视频接口，没有音频编码器——所以带音频的导出会自动改走兼容录制，保证**有声音**。

## 2. 降级决策表

| 环境 | 快速编码 | 兼容录制 | 实际走哪条 | 用户看到什么 |
|---|---|---|---|---|
| Chrome/Edge 94+ 有 AAC | ✅ | ✅ | 快速编码 | MP4 |
| Chrome/Edge 无 AAC（部分国产内核） | ✅ | ✅ | 快速编码 | **MOV**（H.264 + PCM）+ 原因说明 |
| Chrome 无 H.264（极罕见） | VP9 | 仅 WebM | 录制 → 转码 | WebM 或转出的 MP4 |
| Safari 26+ | ✅ | ✅ | 快速编码 | MP4 |
| Safari 16.4–18.7（无 AudioEncoder） | 仅视频 | ✅ | 兼容录制 | MP4（录制） |
| Safari <16.4（无 WebCodecs） | ❌ | ✅ | 兼容录制 | MP4（录制） |
| Firefox 130+ 桌面 | ✅ | ✅ | 快速编码 | MP4 |
| Firefox <130 | ❌ | ✅ | 兼容录制 | WebM → 自动转 MP4 |
| 全都没有 | ❌ | ❌ | — | 导出按钮禁用 + 说明缺什么 |

## 3. 分辨率与画幅

| 目标 | 尺寸（横 / 竖） | K | 可用性 |
|---|---|---|---|
| 720P | 1280×720 / 720×1280 | 0.667 | 全部设备 |
| 1080P（默认） | 1920×1080 / 1080×1920 | 1.0 | 全部设备 |
| 2K | 2560×1440 / 1440×2560 | 1.333 | 桌面；手机端隐藏 |

- 手机端隐藏 2K 是**产品决定**，不是能力问题：2K 在手机上导出会直接把标签页顶到内存上限。
- 分辨率按**短边**换算，竖版不是横版旋转。
- H.264 level 按尺寸自动选（1080 用 4.0，2K 用 5.0），编码器候选里同时给了 `avc1.640028` / `4d0028` / `640032` 三种写法。

## 4. 布局断点

| 宽度 | 布局 | 实测 |
|---|---|---|
| ≥1024 | 两栏（舞台 + 参数面板） | 1920×1080、1536×864（125%）、1280×720（150%）、1366×768 均无横向溢出 |
| <1024 | 单列 | 1024×768 无溢出 |
| <700 | 移动端外壳（两页签 + 自绘下拉） | 390×844、844×390（横屏）无溢出 |

浏览器缩放 100% / 125% / 150% 全部验过：`scrollWidth === innerWidth`，无横向滚动条。

## 5. 素材格式兼容

| 类型 | 支持 | 明确拒绝（导入即报错） |
|---|---|---|
| 图片 | JPG、PNG、WebP、GIF、BMP、AVIF、SVG | HEIC（浏览器解不了，提示转 JPG） |
| 音频 | MP3、M4A/AAC、WAV、FLAC、OGG/Opus、WebM/Opus | WMA、APE、AIFF（Chrome 解码器不支持） |
| 歌词 | LRC、TXT（UTF-8 / UTF-16 / GB2312 / GBK / Big5） | — |
| 叠加素材 | 图片、视频（WebM/MP4） | — |

**为什么要导入时就报**：拖到导出才失败，用户已经等了十分钟。导入时报错只是一秒的事。

## 6. 色彩

| 环节 | 色彩空间 |
|---|---|
| Canvas2D | sRGB |
| Chromium H.264 编码器 | 忽略输入 colorSpace，HD 一律打 BT.709 标签 |
| 预览 vs 导出 | 同一块画布、同一套 `renderAt`，逐像素一致 |
| VP9 解码 | 全范围，必须显式 `fullRange: true`（否则画面被压暗） |

结论：**不需要额外的色彩管理**。P3 图片会被 Canvas2D 转到 sRGB，预览和导出走同一条路，天然一致。

## 7. 设备档位建议

| 设备 | 建议 | 原因 |
|---|---|---|
| 低端安卓（4 GB 内存） | 720P + 快速编码 | 1080P 容易顶到 1.2 GB 护栏 |
| 中端安卓 | 1080P + 快速编码 | 录制只有 17–29 fps，快速编码恒定 30 |
| iPhone（Safari 26+） | 1080P + 快速编码 | 16.4–18 会自动改录制 |
| 老 Windows 笔记本 | 1080P + 快速编码 | 核显编码器约 86 fps |
| 无独显的办公机 | 720P 更快 | 编码吞吐按像素线性下降 |
