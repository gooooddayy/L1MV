# 07 · 回归测试手册

> 24 个探针，跑在真浏览器里（CDP 驱动 Edge），不是 jsdom。
> 因为要测的东西——`VideoEncoder`、`captureStream`、字体栅格化、`performance.memory`——jsdom 一个都没有。

## 1. 目录

```
bench/
├─ run.mjs      通用驱动：起浏览器 → 执行探针 → 回传 JSON
├─ metrics.mjs  空闲 CPU / 堆内存 / GC 后残留
├─ prof.mjs     CPU 采样剖析
├─ shot.mjs     多视口截图
├─ assets_shot.mjs  仓库展示图（截图 + 画布导出）
└─ probes/      24 个用例
```

> 驱动里的 `EDGE` 常量写死了 Windows 的 Edge 路径，换机器改这一行即可。
> 探针本身是纯 `Runtime.evaluate` 表达式，不依赖 Node API，可以直接粘到 DevTools 里跑。

## 2. 怎么跑

```bash
# 通用形式
node bench/run.mjs "<页面绝对路径>" <探针脚本> <headless|window>

# 例：三种导出冒烟
node bench/run.mjs "C:/…/播放器视频生成器.html?debug=1" bench/probes/probe-final.js window

# 例：移动端视口 + CPU 降速 4× + 断网
MOBILE=1 CPU=4 OFFLINE=1 node bench/run.mjs "C:/…/播放器视频生成器.html" bench/probes/probe-lowend.js window
```

| 环境变量 | 作用 |
|---|---|
| `MOBILE=1` | 390×844 视口 + 触摸模拟 |
| `CPU=4` | CPU 降速 4 倍（`Emulation.setCPUThrottlingRate`） |
| `OFFLINE=1` | 断网（`Network.emulateNetworkConditions`） |

**`?debug=1`** 会挂 `window.__app`。正式打开时 `__app` 不存在——这是故意的，调试入口不该出现在成品里。
测试素材由 `bench/seed.js` 提供（`run.mjs` 自动注入，探针里调 `__seedDemo(A)`）：产物本身**不含任何示例素材**。

## 3. 核心用例

| 探针 | 验什么 | 通过标准 |
|---|---|---|
| `probe-final` | 720P / 1080P / 录制 三种导出冒烟 | 三条都出片，`mp4a` 或 `sowt` 存在，时长误差 <0.1 s |
| `probe-rec` | 录制产物可拖动 | `duration` 有限、`seekable` 覆盖全片、能 seek 到中间 |
| `probe-webmpath` | WebM → MP4 转换 | 输出 `avc1 + mp4a`，视频/音频时长差 <0.05 s |
| `probe-aacfail` | 无 AAC 时的 PCM 兜底 | 输出 MOV、`sowt=true`、音频可解码、状态栏有原因 |
| `probe-embedded2` | 5 款内置字体 | 15 组两两签名不同（证明真的换了字形） |
| `probe-concurrency` | 连点导出 / 导出中再点 | 1 个任务、1 个文件、状态一致 |
| `m-longrun` | 10 轮长稳（穿插切页签 + 改字号） | 全部成功、单轮耗时无衰减、堆恒定 |
| `probe-audit` | 布局与渲染质量 | `scrollWidth === innerWidth`、`CLS === 0`、无 28px 以下点击目标 |

## 5. 改完代码的最小验收

按风险从低到高，**至少跑前三项**：

| 改了什么 | 必跑 |
|---|---|
| 样式 / 文案 / 布局 | `probe-audit` + `probe-dpr` + `shot.mjs` 截图 |
| 预览渲染 / 字体 / 特效 | `probe-embedded2` + `probe-interaction` + `probe-final` |
| 导出 / 封装 / 音频 | `probe-final` + `probe-rec` + `probe-aacfail` + `probe-webmpath` |
| 并发 / 状态机 | `probe-concurrency` + `m-longrun` + `probe-fault2` |
| 移动端外壳 | `MOBILE=1` 跑 `probe-nav` + `probe-audit` |

### 出片后必须人耳/人眼确认

自动化只能验容器结构与时长，**这三件事必须人看**：

1. **音画同步**：听开头 3 秒、中间跳一次、结尾 3 秒。
2. **画面与预览一致**：同一时间点截图对比（尤其字体与颜色）。
3. **能拖**：在播放器里拖到 50%，看是否立刻出画。

## 6. 新增一个探针

```js
// bench/probes/probe-xxx.js —— 一个返回对象的 async IIFE
(async () => {
  const A = window.__app, out = {};
  // …操作…
  out.ok = true;
  return out;
})();
```

规矩：
- 不下载文件（把 `HTMLAnchorElement.prototype.click` 打桩成空函数）。
- 不改产品代码；要模拟能力缺失就 patch 原型（例如把 `AudioEncoder.configure` 打桩成抛错）。
- 返回纯 JSON（可 `JSON.stringify`），别返回 DOM 节点。
- 一个探针只验一件事，失败时能一眼看出是哪一步。

## 7. 已知的测量陷阱

| 陷阱 | 表现 | 规避 |
|---|---|---|
| 窗口被判定遮挡 | 耗时随机翻倍 | `--disable-features=CalculateNativeWinOcclusion` |
| headless 的 `captureStream` | 帧率只有 ~27，录制时间被压缩 | 帧率只能真机测 |
| DOM 画布建 `VideoFrame` | 单帧 200 ms | 用离屏画布 |
| `toBlob` 在 headless 不回调 | 测试卡住 | 用 `toDataURL` |
| 后台标签页 | rAF 停摆 | `--disable-renderer-backgrounding` |
