## 2. 发新版本（三条路，按可靠性排）

### A. GitHub 网页上传（最稳，零配置）

1. 打开仓库 → **Add file → Upload files**
2. 拖入新的 `播放器视频生成器.html`（同名会覆盖）
3. Commit message 写清改了什么
4. 打完 tag 后再建 Release（见下）

适合只改一个文件。缺点是每次都要手动。

### B. Git 命令行（网络通的时候最省事）

```bash
git clone https://github.com/gooooddayy/L1MV.git
cd L1MV
# 覆盖文件
git add -A
git commit -m "feat: …"
git push
```

`git push` 在部分网络下会握手失败（`schannel: failed to receive handshake`）。
如果反复失败，直接走 A 或 C，别在这上面耗。

### C. Git Data API（网络只通 api.github.com 时）

思路：`blob → tree → commit → 更新 ref`，详见
[GitHub 官方文档](https://docs.github.com/en/rest/git)。

```bash
# 1) 取当前 head
curl -H "Authorization: token $GH_TOKEN" \
  https://api.github.com/repos/gooooddayy/L1MV/git/ref/heads/main

# 2) 上传 blob（每个文件一次）
curl -X POST -H "Authorization: token $GH_TOKEN" \
  https://api.github.com/repos/gooooddayy/L1MV/git/blobs \
  -d '{"content":"<base64>","encoding":"base64"}'

# 3) 建 tree（带 base_tree 保留其他文件）
# 4) 建 commit（parents = 当前 head）
# 5) PATCH refs/heads/main
```

要点：
- `base_tree` 一定要带，否则会把没在本次提交里的文件删掉。
- `parents` 用当前 head，才是 fast-forward。
- 6.9 MB 的 HTML 走 base64 约 9.3 MB 请求体，一次能过；失败就重试（幂等）。
- **token 只放环境变量，不写进任何文件、不提交。**

## 3. 建 Release

```bash
# 打 tag（指向当前 commit）
curl -X POST -H "Authorization: token $GH_TOKEN" \
  https://api.github.com/repos/gooooddayy/L1MV/git/refs \
  -d '{"ref":"refs/tags/v60.1.0","sha":"<commit sha>"}'

# 建 release
curl -X POST -H "Authorization: token $GH_TOKEN" \
  https://api.github.com/repos/gooooddayy/L1MV/releases \
  -d '{"tag_name":"v60.1.0","name":"…","body":"…","draft":false}'

# 上传资产（upload_url 去掉 {?name,label} 后拼 ?name=）
curl -X POST -H "Authorization: token $GH_TOKEN" \
  -H "Content-Type: text/html" --data-binary @播放器视频生成器.html \
  "https://uploads.github.com/repos/gooooddayy/L1MV/releases/<id>/assets?name=L1MV-v1.0.1.html"
```

**命名固定为 `L1MV-v<版本>.html`**，落地页的「下载」按钮用的是
`releases/latest/download/L1MV-v1.0.0.html`——换版本时要同步改 `index.html` 里的这一行。

上传后核验 `digest` 与本地 `sha256sum` 是否一致（比重新下载快得多）。

## 4. Pages

- 源：`main` 分支根目录，已开启。
- 改完推送后自动重建，约 1 分钟。
- 访问：`https://gooooddayy.github.io/L1MV/`
- 产物页：`https://gooooddayy.github.io/L1MV/播放器视频生成器.html`（URL 里是百分号编码）

**已知问题**：`github.io` 在部分网络下只有几十 KB/s，6.9 MB 要等很久。所以落地页把「下载」放主按钮，「在线试用」放次要位置。

## 5. 发布前检查

- [ ] `node --check` 主脚本通过
- [ ] `grep -c "console.log\|debugger\|TODO"` = 0
- [ ] 无新增外链（`grep "http"` 只应命中 SVG 命名空间与 SEO meta）
- [ ] 720P / 1080P / 竖版 / 2K 各导一条，人耳确认音画同步
- [ ] 无音频、无封面、无歌词 三种情况都能出片
- [ ] 手机视口 390×844 无横向溢出
- [ ] CHANGELOG 已更新
- [ ] 版本号在 `index.html`（下载链接）与 Release 里一致

## 6. 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| Pages 404 | 刚开 Pages / 构建中 | 等 1–2 分钟；看 Actions 里的 `pages build and deployment` |
| 落地页图片不显示 | 大小写不一致或路径写错 | 仓库区分大小写，`assets/xxx.jpg` 必须完全一致 |
| License 显示 NOASSERTION | LICENSE 里混入了额外说明 | LICENSE 只放标准全文，其他说明放 NOTICE.md |
| README 图片不显示 | 用了本地绝对路径 | 一律用仓库相对路径 |
| Release 资产 404 | tag 与 release 不匹配 / 资产还在 `starter` 状态 | 查 `state == "uploaded"` |
| 中文文件名链接失效 | URL 未编码 | 用 `%E6%92%AD...` 形式，或直接让 GitHub 生成 |
| 推送后内容没变 | tree 复用了旧 blob | 校验 `contents` API 的 size/sha，别只看「成功」 |
