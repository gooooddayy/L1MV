# L1MV 播放器视频生成器 · 交付文档

> 单文件、零依赖、离线可用的「歌词播放器」视频生成工具。
> 一份 HTML 双击即用，不需要安装、不需要服务器、断网也能导出。

| 项 | 值 |
|---|---|
| 交付物 | `L1MV.html`（6.62 MB / 5925 行） |
| 运行方式 | 双击打开（file://），Chrome / Edge 94+ 全功能；Safari、Firefox 有降级路径 |
| 外部依赖 | **0**（无 CDN、无字体外链、无统计脚本、无接口） |
| 网络 | 全程不联网；断网、内网、U 盘拷贝均可用 |

## 一、它能做什么

**输入**：一张封面图 + 一段音频（可选）+ 一份 LRC/TXT 歌词（可选）
**输出**：一条带唱片弹出、歌词滚动、光影特效的 MV 视频

| 能力 | 说明 |
|---|---|
| 版式 | 横版 1920×1080（16:9）/ 竖版 1080×1920（9:16） |
| 分辨率 | 720P / 1080P（默认）/ 2K（2560×1440）；手机端隐藏 2K |
| 容器 | MP4（默认）/ MOV；两者同属 ISO BMFF，剪映、PR、微信都认 |
| 导出方式 | **快速编码**（WebCodecs 离线编码，比实时快）/ **兼容录制**（MediaRecorder 录屏） |
| 歌词 | LRC/TXT 解析：`[mm:ss]`、`[mm:ss.xx]`、`[mm:ss.xxx]`、`[mm:ss:xx]` 四种时间戳；同行多时间戳；GB2312/GBK/Big5/UTF-8(BOM)/UTF-16 编码；enhanced LRC 词级标记自动剥离 |
| 封面 | JPG/PNG/WebP/GIF/BMP/AVIF/SVG；>2400px 自动降采样；HEIC 明确拒绝并提示 |
| 音频 | MP3/M4A/AAC/WAV/FLAC/OGG/Opus/WebM；WMA/APE/AIFF 导入即报错（浏览器解不了）；多声道按规则下混成立体声 |
| 字体 | 内置 5 款（宋体、楷体、毛笔、行书、圆润，全部离线）+ 系统已装字体 + 自行导入 ttf/otf |
| 特效 | 水中倒影、左右摇晃、高级光影、胶片颗粒、光扫，可逐项开关与调强度 |
| 叠加素材 | 图片或视频叠加，支持混合模式与透明度 |
| 移动端 | 底部两页签（预览 / 样式）左右跟手翻页；自绘下拉；按设备内存自动降档 |

## 二、怎么用

### 电脑
1. 双击 `L1MV.html`（建议 Chrome / Edge）。
2. 拖入封面、音频、歌词（或点歌词区「点击导入歌词」，也可直接把文件拖进来）。
3. 选格式、分辨率、导出方式，点「导出视频」。
4. 快速编码 ≈ 1.3–2.3× 速（10 秒片约 2–11 秒）；录制 ≈ 1× 速但要保持页面在前台。

### 手机
1. 用 Chrome 或 Safari 打开同一个文件。
2. 底部两个页签左右滑动切换，歌词列表跟在播放条下面。
3. 默认 1080P；内存不够会自动降到 720P 并说明原因。
4. **录制期间别切走、别锁屏**（切走即停并保存已录部分）；快速编码不受影响，但别切后台。

### 三个必须知道的点
- **导出中改参数不影响正在导的那条**：点导出那一刻已做快照（布局、字体、特效、音频、格式全部钉死），改动只影响预览。
- **iPhone 上带音频的 MP4**：Safari 16.4–18.x 没有音频编码器，会自动改走兼容录制以保证有声音。
- **某些国产内核没有 AAC 编码器**：会退成 MOV（H.264 + 未压缩 PCM），状态栏写明原因，剪映可导入。

## 三、技术方案

### 3.1 单文件里装了什么

| 区块 | 体积 | 说明 |
|---|---|---|
| `<style>` | 21 KB | 全部样式内联，无外部样式表 |
| 主脚本 | 191 KB | 一个 `<script>`，无模块、无打包器 |
| 字体数据 | 6.5 MB（96%） | 5 段 `<script type="text/plain">`，浏览器只当纯文本扫过，用到才解码 |

> 字体占 96%，这是文件大小的唯一来源；JS/CSS 加起来只占 3%。

### 3.2 两条导出链路

```
点导出
 ├─ 快速编码（WebCodecs）
 │    buildScene(K) 建独立场景快照 → 逐帧 renderAt → VideoFrame → VideoEncoder
 │    → 自写 MP4 封装（ftyp/moov/mdat，支持 stts 逐样本时长、souv/avcC、©nam/©ART）
 ├─ 兼容录制（MediaRecorder）
 │    cv.captureStream(30) + 音频轨 → MediaRecorder → 碎片 MP4/WebM
 │    → 重封装（碎片 MP4 → 规整 MP4）或 WebM→MP4/MOV 重编码
 └─ 交叉兜底
      快速编码失败（驱动不支持/编码器抛错）→ 自动改录制
      录制只能出 WebM 且有 H.264 编码器 → 自动转 MP4
      没有 AAC 编码器 → 音频写未压缩 PCM，容器改 MOV
      连 H.264 都没有 → 保留 WebM，但补齐时长索引（能播、能拖）
```

### 3.3 音频

- 导入即 `decodeAudioData` 缓存 PCM，导出不再解码；统一 48 kHz。
- 多声道下混规则：3ch=FL/FR/FC，4ch=+BL/BR，5ch=+FC，≥6ch=+LFE(不混入)/SL/SR，`L=FL+K*(FC+BL+SL)`，K=0.7071，逐块 clamp。
- **时长以解码后的样本数为准**，不信文件头（VBR MP3 的头常差 1–2 秒）。
- AAC 编码按 `mp4a.40.2@192k → 128k → 96k → mp4a.40.5@64k → 40.29 → 40.1` 逐档试；全失败才退 PCM。
- 手机端「音频先编、编完放掉 PCM」，峰值从 `PCM + 视频分片` 变成两者取大。

### 3.4 字体

- 5 款免费可商用字体（OFL）子集化为 **4191 字**（GB2312 一级 3755 + ASCII + 中文标点 + 全角 + 常用符号）。
- 数据存在 `#fontStore` 的 `text/plain` 节点里；**选中或导出时才用 `FontFace` 注册**，注册完立刻清空该节点的 base64（省 1–2 MB 常驻）。
- 默认字体是系统字体，所以首屏一个字体都不解码。

### 3.5 稳定性四件套

| 机制 | 防的是什么 |
|---|---|
| **任务号** `beginJob/jobOK` | 上一轮录制的重封装晚到时，覆盖新任务的状态或触发多余下载 |
| **导入序号** | 连续选两段音频/两张图，先发的解码后回来，覆盖新选择 |
| **内存护栏** | 导出中每 32 帧查一次堆，超 1200 MB（手机）/2600 MB（PC）主动停并说明 |
| **日志环** | 200 条环形缓冲，记录启动能力、素材载入、导出起止、失败原因；默认零 console 输出 |

### 3.6 性能关键点

- 首屏：字体移出 CSS（解析 590ms→40ms）+ 首帧渲染延到第一帧之后（FCP 1544→1196ms）。
- 交互：滑块/歌词输入合并到一帧（60 次事件同步阻塞 1506ms→0.7ms）。
- 滚动：去掉页头整宽 `backdrop-filter`、下拉监听收敛成一套、resize 合并到一帧。
- 预览：离屏（IntersectionObserver）时停止重绘。

## 四、关键决策与取舍

| 决策 | 理由 |
|---|---|
| 只做 MP4/MOV，放弃 MKV/WebM 作为主格式 | MKV 浏览器不能编码；WebM 剪映不认，仅作无 H.264 时的保底（并补时长） |
| 不做 4K | 浏览器编码器顶不住，收益低 |
| 质量只做一档（0.12 bpp，手机 0.08） | 实测 0.12→0.08 只掉 0.3 dB PSNR（视觉无损），体积少 38% |
| **PCM 只进 MOV，不进 MP4** | mp4+sowt 在 Chrome 能播，但 `decodeAudioData` 解不出，手机相册/电视更不保证——不赌 |
| 不做 minify / 混淆 | 字体占 96%，去注释+压空白只能省 0.87%，却毁掉可维护性 |
| 不做虚拟滚动 | 1000 行歌词实测导入 36ms、滚动 61fps，改动风险大于收益 |
| 不做双编码器并行 | 实测 2.51/2.48s 对比 2.61/2.44s，核显只有一个编码引擎，排队 |
| 录制「切走即停」而非暂停续录 | MediaRecorder 的 pause/resume 不补偿时间戳，实测少 1.2–1.5s，回来必漂移 |
| 不裁开头 0.4s 热身 | 裁剪点落不到 IDR 会把开头唯一解码起点切掉（变成 3 秒黑屏且拖不回） |

## 五、踩过的坑（按类别）

### 编码与封装
1. **碎片 MP4 不能直接播**：MediaRecorder 写的是「边录边写」的碎片结构，必须解析 stbl 重封装成规整 MP4。
2. **压长帧会把时间轴压短**：早期为消除「暂停造成的超长帧」把大时长压成中位数，低配机上 3.46s 被压成 1.84s → 整条片子加速。已移除。
3. **裁剪必须落在关键帧**：MediaRecorder 的 IDR 间隔能有几秒，裁过头会切掉开头唯一的解码起点（表现：前 3 秒只有声音、进度条拖不回去）。
4. **全片只有 1 个 IDR**：实时录制固有，不重编码无解——拖动进度要解全片。
5. **VFR 不能按固定帧长写**：转换时一律写 1/30 秒，4:06 的片子视频轨被压成 2:50（比例 0.686 正好对上）。改成按相邻时间戳算每帧时长。
6. **WebM 的 Cluster 是「未知长度」**：解析器把它当成「一直到文件末尾」，于是只转了第一个 cluster（6s 录制只转出 3.35s）。
7. **WebM 没有 Duration**：播放器显示 0、放不了。自写 `fixWebm` 重写 Info(Duration) 与规整分簇后才正常。
8. **VP9 是全范围**：解码器默认按有限范围报，画到画布时被压暗（`#112233`→`#011628`）。`configure` 里显式 `fullRange:true` 才对上。
9. **Chrome 把视频帧写成 BlockGroup**，关键帧标志位不填——按「没有 ReferenceBlock 就是关键帧」判断。
10. **宽高/采样率藏在 `Video(0xE0)`/`Audio(0xE1)` 子元素里**，第一层 TrackEntry 上是空的，直接读会得到 0×0。
11. **AAC 有 priming**：Chrome 会加 2–3×1024 个样本，容器时长虚高 60–80ms，用 elst 校正。

### 音频
12. **`<audio>.duration` 读的是文件头**：VBR MP3 常差 1–2 秒，时长基准跟着错，成片尾部多出等长静音（4:06 导成 4:08 的真凶）。改为按解码样本数校正。
13. **AAC 编码器会挑码率**：有的安卓内核 192k 直接拒绝、128k 能编。现在逐档重试。
14. **`isConfigSupported` 会撒谎**：查询说没有 AAC，真编却能出来。改成「真编 4096 帧」判断（1024 帧会让 `flush` 报错，那是探测方法的问题）。
15. **自己挖的坑**：曾把 `audioCodec` 写成 `'pcm'` 传给 `configure`，必抛「Unsupported channel count … received 0」，导致每次都被动退 PCM。编码器名必须是真实编码器。

### 字体
16. **CSS 注释少写 `*/`**：把后面 6.6 MB 样式整段吞掉，页面还能开、字体全部失效。大段注入后必须校验配对。
17. **字体是按需加载的**：切字体当帧仍是回落字体，必须等 `FontFace.load()` 完成再清字形缓存重绘；导出前也要 `await`。
18. **字体探测挡首屏**：对每个系统字族做 3 次 canvas 测量，实测 130ms，已挪到空闲时。
19. **6.4 MB base64 写进 `<style>`**：CSS 解析器逐个 token 做词法分析+字符串驻留，首屏 2.8s。移到 `text/plain` 后解析降到 40ms。

### 移动端
20. **页签条在脚本之后才解析**：`getElementById('mtab')` 拿到 null，改用文档级事件委托。
21. **自绘下拉被翻页容器裁切**：`.pager` 有 transform + overflow，菜单必被裁。挂到 `body` 上用 fixed 定位，并按按钮位置自动上下翻转。
22. **菜单点内部/滚动就关**：`document` 的 click/scroll 没有排除自身。加了 `menu.contains(e.target)` 判断与 `overscroll-behavior:contain`。
23. **同时能开多个下拉**：关闭函数挂在 `select.__msel`，遍历拿到的却是 `wrap`。补 `wrap.__msel` 才互斥。
24. **菜单里残留已删选项**：先建自绘菜单、后删原生 `<option>`，菜单是快照。顺序必须反过来。
25. **自动降档不会触发 `change`**：程序赋值要手动 `syncNiceSelects()`。
26. **320px 下「快速编码」被截成「快速编」**：手机端换两字标签。

### 性能
27. **`requestAnimationFrame` 回调在绘制之前**：想「先画首屏再干活」，单级 rAF 等于白推，必须两级。
28. **整宽 `backdrop-filter` 是滚动杀手**：sticky 页头每帧对整条宽度做 14px 高斯模糊。
29. **滑块每 input 全量重建**：拖一次字号等于几百次 `buildLayout + renderAt`，同步阻塞 1506ms。合并到一帧后 0.7ms。
30. **连续切页签会排多个 rAF**：同一帧里重绘多次，必须去重。
31. **每个下拉各挂 3 个文档级监听**：4 个下拉 12 个，每个 scroll 事件全跑一遍且无条件写 class。
32. **实测无收益、别再试**：双画布交替、队列深度 4/8/12、软件编码、`latencyMode:'realtime'`、`bitrateMode:'constant'`、双编码器并行。

### 并发与异常
33. **晚到的回调改新任务状态**：上一轮重封装结束时直接 `setStatus`/下载，界面出现「文件下好了、状态是上一次的」。用任务号解决。
34. **异步导入竞态**：先选的大图后解码完，覆盖新选择。用导入序号解决。
35. **异常未捕获会卡在「导出中」**：`captureStream` 在个别内核直接抛。整体包 try/catch 并复位 busy/recording/进度条。

### 测量工具本身的坑
36. **窗口移到屏幕外会被判「被遮挡」**：Chromium 节流合成器/GPU，耗时忽高忽低（17/29/49ms）。必须加 `--disable-features=CalculateNativeWinOcclusion`。
37. **用 DOM 里的画布建 VideoFrame 会走合成器读回**：单帧 200ms。测编码必须用离屏画布。
38. **headless 里 `captureStream` 帧率低、录制时间被压缩**，不能用来测真实帧率。
39. **`canvas.toBlob` 在 headless 偶发不回调**：测图片导入改用 `toDataURL` 同步构造。

## 七、已知限制（不打算修）

| 限制 | 原因 |
|---|---|
| 录制成片开头约 0.4 s 静止 | MediaRecorder 起录热身，裁掉会切走开头关键帧（得不偿失） |
| 录制全片只有 1 个关键帧，拖动要解全片 | MediaRecorder 固有，不重编码无解 |
| 手机录制帧率只有 17–29 fps | 1080p + 特效全开的实际渲染能力；选 720P 可提高 |
| 某些内核没有 AAC → 只能 MOV | MP4 只认 AAC；PCM 塞进 MP4 兼容性更差 |
| 60 分钟长片未实跑 | 有预算拦截 + ETA + 分级提醒，属已知边界 |
| Safari / Firefox 未真机验证 | 无设备；已做能力自检与降级，缺什么会在状态栏说明 |

```
    ├─ bench/                     ← 回归测试工具（Node + CDP 驱动 Edge）
    │   ├─ run.mjs                ← 通用驱动：起浏览器 → 执行探针 → 回传 JSON
    │   ├─ metrics.mjs            ← 测空闲 CPU / 堆内存 / GC 后残留
    │   ├─ prof.mjs               ← CPU 采样剖析
    │   ├─ shot.mjs               ← 多视口截图
    │   ├─ probes/                ← 24 个用例（导出/录制/字体/并发/长稳/低端…）
    │   └─ patches/               ← 历史改动用过的补丁脚本（备查）
    ├─ fonts/                     ← 字体子集源文件（重新生成时用）
    └─ memory/                    ← 逐日变更日志与长期笔记
```

### 怎么跑回归

```bash
# 通用形式：run.mjs <页面绝对路径> <探针脚本> window
node .workbuddy/bench/run.mjs "C:/…/L1MV.html?demo=1" \
     .workbuddy/bench/probes/probe-final.js window
```

> `?demo=1` 会载入内置示例并挂载 `window.__app`（调试入口只在这个参数下存在）。
> 需要移动端视口加 `MOBILE=1`，需要 CPU 降速加 `CPU=4`，需要断网加 `OFFLINE=1`。

**核心用例**：`probe-final`（三种导出冒烟）、`probe-rec`（录制可拖）、`probe-webmpath`（WebM 转换）、`probe-aacfail`（PCM 兜底）、`probe-embedded2`（5 款字体）、`probe-concurrency`（连点）、`m-longrun`（10 轮长稳）、`probe-audit`（CLS/DOM）。
